# ANA real label snapshots 1.70.34

The version 33 sync fingerprint included only label ID/count and daily activity. Exchanging labels between two chats with unchanged totals or renaming a label could therefore send only a heartbeat and leave the per-chat database snapshot stale. The ANA fingerprint now includes a stable sorted catalog (ID, name, color, count) and per-chat membership (real chat ID, phone and unique sorted label IDs). Reordering identical data does not publish again. Other seller fingerprints remain unchanged.

An ANA read without explicit `labels_confiavel=true` sends only the existing heartbeat and preserves both the confirmed fingerprint and movement snapshot. It does not interpret an unknown read as an empty label set. Profile-photo refresh remains before this gate. Version 33 quoted replies, exact message IDs and media behavior are preserved.

The live `wa-sync-labels` Edge version 24 returns `chat_labels_raw` before its 5,000-row limit, `chat_labels_filtered` after its phone/label-array validation and `chat_labels` after successful upsert chunks. ANA now requires HTTP success plus `ok=true`, `heartbeat=false` and matching raw/filtered/upsert counts before advancing either snapshot. Missing, rejected or partial acknowledgements retry on the existing alarm. Empty per-chat label arrays remain valid. Other sellers retain their existing acknowledgement behavior.
